# Config Atlas

Терминальное приложение, которое отвечает на вопрос «а где лежит конфиг для X?».

Сканирует macOS, собирает карту всех конфигов (AI-ассистенты, Git, GitHub, SSH,
сеть/VPN, shell, Node, Python, Docker, IDE, системные) и показывает их в TUI
с превью содержимого.

**Приложение только читает файлы.** Ничего не создаёт, не меняет и не удаляет.

## Запуск

```sh
config-atlas              # интерактивный TUI
config-atlas --list       # текстовый список (удобно для grep/less)
config-atlas --chains     # приоритет конфигов: какой файл применяется
config-atlas --env        # индекс переменных окружения
config-atlas --grep proxy # поиск по содержимому файлов
config-atlas --json       # выгрузка карты в JSON
```

Скрипт-обёртка лежит в `~/.local/bin/config-atlas`, исходники — здесь.

## Как связать с агентами: MCP-сервер

`atlas_mcp.py` — MCP-сервер на stdio. Агент получает семь инструментов:

| Инструмент | Что делает |
|---|---|
| `find_configs` | найти конфиги по названию, пути или описанию |
| `read_config` | прочитать файл (секреты маскируются по умолчанию) |
| `explain_config` | какой файл из цепочки реально применяется и почему |
| `grep_configs` | поиск по содержимому файлов, с номерами строк |
| `list_env` | переменные окружения и **где** они заданы |
| `list_chains` | список цепочек приоритета |
| `map_overview` | сводка: сколько путей, цепочек, переменных |

Плюс ресурс `atlas://categories` — список категорий со счётчиками.

Секреты маскируются всегда, кроме явного `reveal_secrets=true` в `read_config`.

**Уже подключено** к Claude Code (`~/.claude.json`) и opencode
(`~/.config/opencode/opencode.jsonc`):

```jsonc
// ~/.claude.json
"mcpServers": {
  "config-atlas": {
    "type": "stdio",
    "command": "uv",
    "args": ["run", "--quiet", "--script",
             "/path/to/atlas_mcp.py"]
  }
}
```

```jsonc
// ~/.config/opencode/opencode.jsonc
"mcp": { "servers": {
  "config-atlas": {
    "type": "local",
    "command": ["uv", "run", "--quiet", "--script",
                "/path/to/atlas_mcp.py"],
    "enabled": true
  }
}}
```

Подключить к другому клиенту — одна строка:

```sh
claude mcp add config-atlas -- uv run --script \
    ~/Projects/config-atlas/atlas_mcp.py
```

Теперь можно спрашивать агента прямо в диалоге:

- «где у меня настроен прокси?» → `find_configs("proxy")`
- «почему мой git не берёт настройки из ~/.gitconfig?» → `explain_config("git")`
- «где задаётся токен?» → `grep_configs("TOKEN")`
- «что за переменная NVM_BIN?» → `list_env("NVM_BIN")`

### Почему сервер читает login-shell

MCP-сервер запускает агент, и окружение у него бывает урезанным — часть
переменных ещё не задана. Поэтому живые переменные берутся не из `os.environ`
сервера, а из login-shell (`zsh -lic env`) — это ровно то, что получит новый
терминал. Результат кэшируется.

## Интерфейс

Одна колонка, как в Claude Code: сверху заголовок, потом результаты, внизу —
строка ввода и подсказки.

```
✻ Config Atlas   карта конфигов этого Mac
358 путей · 223 на диске · 22 цепочек · 20 переменных

● ~/.config/opencode/opencode.jsonc  ✓  opencode
● ~/.claude/settings.json            ✓  Claude Code
▸ ~/.claude                          Claude Code
● ~/.codex/config.toml               Codex CLI
...

opencode · AI / Ассистенты · ✓ применяется · глобальный · 6.8 KB · изменён …
Главный конфиг opencode: тема, модель, плагины, MCP-серверы, agent
~/.config/opencode/opencode.jsonc

╭──────────────────────────────────────────────────────────╮
│ ❯ Найти конфиг: ssh, proxy, opencode…                    │
╰──────────────────────────────────────────────────────────╯
                                        Все конфиги  211  enter открыть  ^y путь
```

Четыре режима переключаются `Tab`:

| Режим | Что показывает |
|---|---|
| **Все конфиги** | все найденные и описанные пути |
| **Приоритет конфигов** | ✓ какой файл реально применяется, ✗ какой перекрыт |
| **Переменные окружения** | где заданы переменные — файл и строка, плюс живые |
| **Поиск по тексту** | результаты grep по содержимому конфигов |

### Переменные окружения

В режиме «Переменные окружения» видно **и откуда взята каждая переменная**:

```
PATH   задана 9 раз — действует последняя
  ~/.profile:2     "$PATH:~/.docker/bin"
  ~/.zshrc:115     ~/.opencode/bin:$PATH
NVM_BIN
  ⚙ только в окружении   ~/.nvm/versions/node/v24.6.0/bin
```

- `~/.zshrc:115` — переменная задана в файле конфигурации, указана строка
- `⚙ только в окружении` — задана системой, launchd, профилем IDE или
  родительским процессом; в конфигах её нет

Живые переменные читаются из login-shell (`zsh -lic env`) — это то же, что
получит новый терминал. Команда `/globals` отключает их показ.

## Управление

| Клавиши | Действие |
|---|---|
| `↑` `↓` / `PgUp` `PgDn` | перемещение по списку |
| `Enter` | открыть превью файла (в «Поиске по тексту» — запустить поиск) |
| `Tab` / `Shift-Tab` | сменить режим |
| `Esc` | очистить запрос, затем фильтры |
| `/` | палитра команд и категорий |
| `Ctrl+Y` | скопировать путь в буфер обмена |
| `Ctrl+O` | открыть в редакторе (`$EDITOR`, иначе TextEdit) |
| `Ctrl+F` | показать в Finder |
| `Ctrl+T` | перейти к цели симлинка |
| `Ctrl+R` | пересканировать систему |
| `F1` | справка |
| `Ctrl+C` | выход |

В превью: `c` — копировать путь, `o` — открыть, `f` — Finder, `m` — секреты,
`Esc` — закрыть. Работает мышь: клик по строке выбирает её.

### Команды (`/`)

| Команда | Действие |
|---|---|
| `/all` `/chains` `/env` `/grep` | переключить режим |
| `/ai` `/git` `/github` `/ssh` `/net` `/shell` `/node` `/py` `/docker` `/ide` `/macos` `/apps` `/misc` | фильтр по категории |
| `/clear` | сбросить категорию и запрос |
| `/missing` | показать/скрыть отсутствующие файлы |
| `/secrets` | показать/скрыть секреты в превью |
| `/globals` | глобальные переменные окружения (вкл/выкл) |
| `/source` | источник: все → курируемые → найденные |
| `/rescan` | пересканировать систему |
| `/help` | справка |
| `/quit` | выход |

## Обозначения

- `●` — файл существует, `○` — не существует
- `▸` — папка, `→` — симлинк
- `✓` / `✗` — в цепочке приоритета: применяется / перекрыт
- `↩` — тот же файл, что и выше по списку (дубликат в другой категории)

## Как это устроено

```
config_atlas.py          данные и CLI (только стандартная библиотека)
├── CATALOG       234 вручную описанных пути (путь → что это)
├── CHAIN_GROUPS  22 цепочки приоритета (какой конфиг побеждает)
├── scan_home()   автопоиск: дотфайлы HOME, ~/.config, Application Support,
│                 Preferences, LaunchAgents, /etc
├── HINTS         эвристика «имя папки/файла → категория»
├── search()      fuzzy-матчинг (подстрока > подпоследовательность)
├── grep_entries()  поиск по содержимому файлов
├── build_env_index()  индекс переменных окружения (из файлов + живые)
└── login_shell_env()  переменные нового терминала (zsh -lic env)

atlas_tui.py             интерфейс (Textual)
atlas_mcp.py             MCP-сервер для агентов
```

Интерфейс сделан на [Textual](https://textual.textualize.io/) — как
OpenCode и Claude Code. Зависимость одна, ставится автоматически через `uv`
(в `atlas_tui.py` объявлена в PEP-723-метаданных, так что `uv run --script`
подтягивает её сам). Слой данных в `config_atlas.py` остался на чистом stdlib
и не зависит ни от чего — CLI работает без установки пакетов.

### Цепочки приоритета

Отдельный список `CHAIN_GROUPS` описывает, какой конфиг из нескольких
кандидатов реально применяется. Уровни идут от общего к частному:

```python
Chain("opencode", "opencode", "ai", [
    ("глобальный", ["~/.config/opencode/opencode.jsonc"]),
    ("проектный",  ["./opencode.json", "./opencode.jsonc"]),
], "Проектный opencode.json полностью перекрывает глобальный")
```

Внутри уровня действует правило «первый существующий» (XDG-путь заменяет
legacy-путь), между уровнями — «последний существующий побеждает».
Уровни, где файлы читаются подряд (zsh: zshenv → zprofile → zshrc),
перечисляются в поле `stack`.

### Курируемый каталог

Основной источник — `CATALOG` в начале файла: список кортежей
`(категория, приложение, путь, описание)`. Чтобы добавить свой путь,
допиши строку туда. Перезапусти приложение — всё подхватится.

Пути с `~` разворачиваются автоматически. Если один и тот же файл состоит в
нескольких категориях (например, `~/.npmrc` — это и Node, и «сеть/прокси»),
он показывается в основной категории, а в остальных — со значком `↩`.
Основную категорию можно задать в словаре `PRIMARY_OVERRIDE`.

## Что сканируется

| Источник | Что берём |
|---|---|
| `~/` | дот-файлы (`~/.gitconfig`, `~/.npmrc`, `~/.zshrc`, …) |
| `~/.config/**` | все файлы с конфиг-расширениями, глубина до 4 |
| `~/Library/Application Support/<App>/*` | верхний уровень каждого приложения |
| `~/Library/Preferences/*.plist` | plist'ы нормальных приложений (не `com.apple.*`) |
| `~/Library/LaunchAgents` | launchd-агенты |
| `/etc` | точечный список системных конфигов |

Автопоиск отсекает мусор (кэши, крэш-репорты, телеметрию, `RemoteFeatureFlags`).
Всё, что найдено, но не описано вручную, попадает в категорию
«Приложения (данные)» или «Разное».

## Безопасность

- Приложение ничего не пишет на диск (кроме `pbcopy` в буфер обмена).
- Секреты в превью замаскированы по умолчанию. Маскируются:
  - значения по ключам `token`, `secret`, `password`, `api_key`, `auth` и т.п.
  - непрозрачные длинные значения (base64/hex) в переменных окружения
  - пары вида `user:password`
  Команда `/secrets` (или `m` в превью) показывает реальные значения.
  Маскинг не срабатывает на безобидных значениях вроде `PATH` и `HOME`.

## Как библиотека

Модуль импортируется без побочных эффектов:

```python
import sys, os
sys.path.insert(0, os.path.expanduser("~/Projects/config-atlas"))
import config_atlas as ca

entries = ca.build_map()          # list[Entry] — вся карта
hits = ca.search(entries, "proxy")
```

Публичный API: `build_map()`, `search(entries, query)`, `Entry`, `CATALOG`,
`CATEGORIES`, `read_preview(path)`, `mask_secrets(lines)`, `expand(path)`.

Готовый пример — `examples/find_config.py`:

```sh
python3 examples/find_config.py proxy          # где прокси?
python3 examples/find_config.py gh --cat       # только в категории GitHub
python3 examples/find_config.py npmrc --show   # + показать содержимое
```

## Тест-утилиты

`tools/` — проверка без терминала:

```sh
uv run --script tools/tui_tests.py    # сценарии TUI: клавиши, режимы, мышь, скролл
uv run --script tools/mcp_tests.py    # MCP-сервер через настоящий MCP-клиент
uv run --script tools/term_guard.py   # терминал восстанавливается при любом выходе
uv run --script tools/tui_shots.py /tmp/shots   # скриншоты экранов в SVG
```

`tui_tests.py` прогоняет реальные сценарии в `run_test()`: поиск, палитра
команд, переключение режимов, превью, справка, мышь, скролл колесом,
глобальные переменные. `tui_shots.py` снимает экраны в разных состояниях —
удобно смотреть вёрстку. `mcp_tests.py` поднимает MCP-сервер и проверяет все
инструменты, включая что секреты не утекают в ответах. `term_guard.py`
проверяет, что после SIGTERM/SIGHUP/SIGINT/SIGQUIT/SIGKILL терминал
остаётся в рабочем состоянии.

`tools/fake_term.py` — эмулятор терминала для этих проверок: считает
включённые и выключенные режимы (DECSET/DECRST) и отвечает на запросы
терминала.

## Защита терминала

Textual переключает терминал в альт-экран, прячет курсор и выключает
перенос строк. Если приложение умирает нештатно, терминал остаётся в этом
состоянии: вы видите пустой экран, курсора нет, `Enter` не работает, шелл
не печатает ничего. Восстановить помогает `reset`.

Здесь от этого защита двухслойная:

1. `install_terminal_guard()` в `atlas_tui.py` — обработчики SIGTERM,
   SIGHUP, SIGINT, SIGQUIT плюс `atexit`. Важная деталь: писать нужно
   **напрямую в файловый дескриптор**, потому что Textual перенаправляет
   `sys.stdout` и `sys.stderr` в свои буферы, и запись через них никуда
   не уходит.
2. Обёртка `~/.local/bin/config-atlas` не делает `exec`, а запускает
   приложение в фоне и ждёт его. Если приложение убили SIGKILL (сигнал
   перехватить невозможно) — обёртка дожидается выхода и восстанавливает
   терминал сама.

Ещё одна тонкость: обёртка запускает Python **напрямую из venv**, а не
через `uv run`. `uv run` — это обёртка над обёрткой: при SIGTERM она
убивает дочерний Python, не передавая ему сигнал, и приложение не
успевает восстановить терминал.

## Замечания о вёрстке

Textual считает ширину текста правильно, но `rich` не умеет `no_wrap` у
многострочных `Text`, а `truncate()` теряет оформление. Поэтому в
`atlas_tui.py` есть собственный обрез:

```python
fit(text, width)   # обрезает каждую строку по ширине, сохраняя стили
cut(text, width)   # то же для одной строки
```

Если будешь добавлять вывод — режь текст через `fit()`, иначе длинные
русские строки начнут переноситься и ломать колонки.
